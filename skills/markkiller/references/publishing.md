# 在线阅读与版本存档

默认交付本地自包含 HTML。用户明确要求公开网页时，沿已授权的仓库和托管目标发布，优先已有 Git/CLI/API 能力。一次明确的发布授权无需重复询问；普通生成阅读版本身不授权公开私人材料。

GitHub 仓库里的 HTML 文件页和 Release 附件主要用于查看源码或下载；点击就读应使用 GitHub Pages 等静态托管的实际页面地址。已有 GitHub 仓库可选择 main 的 /docs 发布源；按当前官方文档核配置。目录里提供 index.html 作为入口，纯静态站可放 .nojekyll，避免不必要的模板处理。

小批可直接发布单文件阅读版。多篇大文件可使用带封面的索引加独立单篇 HTML，保留主题/时间分类，并提供完整离线版。链接用站点内相对路径，适配项目子路径；不要把本机路径、GitHub blob 或 raw 地址当成在线阅读入口。索引可以调用 reader.py 的 build(data, base, index_only=True, item_links={id: "article.html#item-1"})；每篇的锚点应按该单篇实际生成序号填写。

从总览进入独立单篇后，“内容地图”应返回同一批总览，而不是该单篇的一行目录。生成独立页时传 `build(single, base, collection_index="index.html#map")`，或CLI的 `--collection-index index.html#map`；合集和总览不传，保留页内 `#map`。明确链接不依赖浏览器历史或referrer，因此直接打开单篇也能返回。发布验收走完“总览→单篇→内容地图→总览”，并核作品数量恢复。

只复制已审阅读输出及必要公开资产到发布目录。私人目录、筛选排除列表、完整字幕、认证信息和过程日志不随结果发布。原题、作者、普通来源链接和必要原作配图保留；对公开派生做来源与隐私检查。

每次迭代保留独立版本文件。发布后核分支/提交与部署状态，再请求最终 HTTPS 地址，确认成功响应、text/html、正文内容与目标版本一致；真实浏览器核封面、正文、图和跳转。若部署成功但浏览器工具不可用，分别报告 HTTP 验证与视觉未验，不相互冒充。README 示例和仓库主页指向实际在线地址；ZIP 下载作为离线保存选项。
