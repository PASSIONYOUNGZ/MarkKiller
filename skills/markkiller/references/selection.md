# 按条件识别收藏内容

当用户要求“只看 AI”“排除新闻，只要实操”等条件时，在深读前建立筛选账本。它不同于成品 HTML 的主题筛选：前者决定采集和解读哪些作品，后者只控制已交付内容的显示。

## 识别与选择

先把自然语言条件写入 request：纳入主题、排除项、数量、计数单位、排序与范围。默认“AI 方面”包含人工智能原理、模型、工具应用、开发、评测及明确围绕 AI 的职业/产业分析；普通编程、设计、数码或标题里偶然出现 AI 不自动纳入。用户更具体的条件优先。不要把这份示例范围固定为所有人的定义。

从实际收藏目录读取稳定作品 ID、原题、作者、简介、可用标签及收藏来源。文件夹名只是线索，混合收藏要看条目。按目录批次作语义判断：明确相关可进入候选；明确无关记排除及简短原因；含糊、失效或信息不足记待核，再查看简介、章节或必要正文。关键词用于缩小检索，不能替代语义判断，也不能以关键词未命中证明不相关。收藏目录与追更合集分开；后者的整套投稿不自动算用户逐条收藏。

候选经正文确认主题符合、材料可支持解读后才选入。保留具体依据，如“简介说明用大模型构造检索问答；正文 02:10 演示检索失败”，不用“标题含AI”充当最终依据。主题相关与学习价值是两项判断；只有用户要求质量筛选时才以价值排除，不擅自删掉符合范围的指定作品。

跨收藏夹重复按平台/作品ID/版本去重并保留所有来源。普通“N条视频”按独立作品计数；课程中的N节不能静默冒充N条独立收藏。数量按目标上限处理，明确要求足额时才用 exact；用户已说明不足按实际交付，就不重复询问。发现主要是长课程且数量不足时，先核目录；若需要改变计数口径，再向用户确认是否按课程分集计数。只做一节不算全课已解读。数量不足不从外部热门视频补齐；可以继续检查授权收藏范围，或报告实际缺口。停止时说明已核目录与未核边界，不把有界筛选写成全账户已穷尽。

## 本地筛选账本

selection.json 使用 schema_version=1，包含 criteria（原话及解释）、requested_count（正整数）、count_unit（work 或 part）、catalog_boundary（已检查范围与停止证据）、entries。每条含：

- id：本账本唯一ID；platform、work_id、version（可省略）、part（按分集时必填）。
- title、source_url：原题与正常阅读链。
- favorite_sources：非空数组，记录实际收藏目录原链或有来源的导入目录，不放认证参数。
- decision：candidate / selected / excluded / uncertain；reason：具体判断理由。
- evidence：数组，每项含 kind（title / description / chapter / transcript / visual）、text（与条件相关的事实）、locator（页面或原稿定位）。
- selected 条目另填 reader_ids：对应阅读数据 ID，可先空数组表示尚未写成。

`python -X utf8 scripts/check_selection.py --input selection.json [--reader reader.json] [--require-count]` 检查来源、重复作品、依据和交付对应；输出选中数量、已完成数量及缺口。未使用 --require-count 时允许保存不足数量的阶段账本；使用时必须足额完成。脚本只验证结构与计数，不替 Agent 判断是否真属该主题或内容是否读懂。待核不能计入已完成；修改条件后重评旧结论。

账本、被排除条目和私人目录默认留本地。读者页只说明筛选条件、实际篇数和影响理解的覆盖边界；公开发布时仅输出用户授权的选中解读，不连带公开整个收藏目录。
